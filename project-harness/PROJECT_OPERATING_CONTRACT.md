# DYAI Studio Project Operating Contract

## Purpose
Maintain one coherent line from business intent to delivered evidence.

## Traceability
Strategic intent → customer problem → product goal → requirement/hypothesis → Jira work → implementation/document change → verification evidence → production/customer observation → business learning → reusable asset.

## Systems of record
- Confluence space DYAIStudio: product, business, decisions, controlled documentation.
- Jira project DYAI / board 733: executable work state.
- GitHub DYAI2025/DYAI-Studio: code and technical evidence.
- Runtime/production: real-boundary evidence when available.

## Delivery
Primary model: Kanban.
WIP should favour one meaningful end-to-end slice over parallel unfinished experiments.

## Change policy
A material change to positioning, primary audiences, offer architecture, release scope or evidence policy requires:
1. explicit rationale;
2. contradiction check against current Confluence truth;
3. owner decision if direction changes;
4. affected Jira/backlog update;
5. implementation/docs update where relevant.

## Product-value test
No feature is justified by technical novelty alone. It should improve at least one of:
recognition, comprehension, trust, qualified conversion, customer outcome, learning speed or reusable leverage.

## Claim policy
Do not claim:
- customer value without evidence;
- ROI without a defensible baseline;
- production behaviour from local tests;
- market validation from internal enthusiasm;
- repeatability from a single successful example.

## Release policy
G4 remains blocked until the release candidate has evidence appropriate to implemented scope for:
- deployment/runtime;
- accessibility;
- performance;
- security/privacy;
- forms/integrations;
- bilingual parity;
- analytics;
- owner acceptance.

## Asset policy
Promote assets through:
Experiment → Used → Repeated → Productised.
Promotion requires evidence from the relevant maturity stage.

## Human authority
Ben is Product Owner/Sponsor. AI agents can challenge, recommend and execute authorised bounded work, but cannot silently redefine product direction or accept residual business risk on Ben's behalf.
